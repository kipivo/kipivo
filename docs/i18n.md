# Internationalization for the Web app

**Status: proposal, not implemented.** Start with English (`en`, the source catalog) and Simplified Chinese (`zh-CN`). Use `use-intl` directly for messages and formatting, TanStack Start for request and document state, and a device preference rather than an account setting. These are proposed launch languages, not constraints of the library.

## What owns what

| Concern                              | Decision                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI copy, ICU messages and formatting | Install `use-intl` in `apps/web`. Components call `useTranslations('auth')` / `useFormatter()` directly. No second translation context or wrapper around `t`.                                                                                                                                                                                 |
| URL and identity                     | Keep `/`, `/sign-in`, `/authorize`, `/settings` and callbacks unchanged. The same link opens in the reader's preferred language. Do not rewrite `/rpc`, `/api/*`, assets or health checks. If public pages later need independently indexed translations, consider locale-prefixed URLs for those pages, not for the whole authenticated app. |
| Persistence                          | A host-only `kipivo-locale` cookie is the only explicit preference in v1. Offer **English**, **简体中文** and **Use browser language** in the shared header, including before sign-in. Resetting deletes the cookie. Do not put this under settings that promise to follow the account across devices.                                        |
| Workspace boundary                   | Web owns its catalog. `@kipivo/ui` accepts localized labels/slots (including dialog close and theme selector accessible names); English defaults keep existing consumers and stories usable. No Web imports or required app provider inside shared UI. Do not change Mobile, CLI, database, API schemas or auth emails in v1.                 |

## One language from HTTP request to interactive screen

1. Put a pure, tested resolver in `apps/web/src/features/i18n/locale.ts`. A valid explicit cookie wins; otherwise negotiate `Accept-Language` by quality and original order. Match supported tags case-insensitively; also map `en-*` → `en` and `zh`, `zh-SG`, `zh-Hans` or `zh-Hans-*` → `zh-CN`. Do not label Traditional Chinese as supported: skip `zh-Hant-*` and bare `zh-TW/HK/MO` and try the next preference. Ignore invalid choices and zero-weight ranges; absent a supported preference, serve the English default. Test e.g. `zh-TW, en-GB;q=0.8` → `en`, and a `zh-CN` cookie over an English header → `zh-CN`.
2. The root **loader** calls a read-only [Start server function](https://tanstack.com/start/latest/docs/framework/react/guide/server-functions). Its `.server.ts` helper reads the incoming cookie/header and loads only the selected catalog from an explicit locale-to-import map. Return serializable `{ locale, preference, messages, timeZone }` (`preference` is the explicit locale or `null` for automatic); no translator functions, request headers or account lookup in loader data. Keep the root data fresh across ordinary SPA navigation (`staleTime: Infinity`); an explicit language change invalidates it. No module-level current locale, and no second client-side guess from `navigator.language` or `localStorage`.
3. `__root.tsx` reads that snapshot for `<html lang>` and `<IntlProvider>` around the app, including 404 and account UI. Hydrate from the same loader data. Build route titles in `head` using the root match's data and `createTranslator` (no hooks); retain existing security meta tags. Set `timeZone: 'UTC'` for consistently labeled absolute timestamps until a separate time-zone preference exists. If SSR ever needs relative time, pass the same reference instant to both renders. Language is not a time zone.
4. On an explicit switch, a validated same-origin POST server function sets or clears the cookie (`Path=/`, `SameSite=Lax`, `HttpOnly`, `Secure` on HTTPS, bounded lifetime). Await success, then [`router.invalidate()`](https://tanstack.com/router/latest/docs/framework/react/guide/data-loading) and read the new root data. Update title, `lang`, and visible/accessible copy together. Keep the old UI and offer retry on failure. **Do not reload the document or key the route subtree by locale:** the password reset screen removes the token from the URL fragment and keeps it in memory; reloading would lose it. Preserve typed inputs and authorization search params as well.
5. Serve locale-dependent HTML and locale-reading server-function responses with `Cache-Control: no-store` in v1, including signed-out pages. Extend the existing Web cache rules where needed; leave hashed JS/CSS assets cacheable. This avoids a shared cache replaying another visitor's language. Measure the selected catalog's serialized size before adding per-route chunks; v1 doesn't warrant a catalog waterfall per route.

## Messages and boundaries

Start with `apps/web/src/features/i18n/messages/en.json` and `zh-cn.json` (the **locale tag** remains `zh-CN`). Group by feature, e.g. `auth.signIn.title`, `settings.save.pending`, `runs.status.failed`; reserve `common` for strings with the same meaning in every context. Store keys or error codes in state, not already-translated text. Use ICU for whole sentences; translators must be able to reorder the count, name, or rich link without changing JSX.

| Key                   | `en`                                          | `zh-CN`                             |
| --------------------- | --------------------------------------------- | ----------------------------------- |
| `runs.history.count`  | `{count, plural, one {# run} other {# runs}}` | `{count, plural, other {# 次运行}}` |
| `auth.authorize.open` | `Open {appName}`                              | `打开{appName}`                     |

Use the English catalog to type namespaces and keys. In a Web unit test compare leaf paths in both directions, parse ICU messages, and compare named arguments, argument kinds and rich-text tags. Require `other` for plurals, **not** identical plural categories across languages. Declare the chosen ICU parser in the importing workspace if the test imports it directly. Fail CI for a bad catalog. Treat a runtime missing key as an unexpected defect: report locale + key (no interpolated user data). If a selected catalog fails to load, return the English snapshot **with `locale: en`**. For an unexpected individual missing key, keep the rest of the page usable via the library’s message fallback; do not ship a second catalog to every browser as insurance.

Map stable run statuses, RBAC permissions and known API/auth failures to typed keys in their owning feature. For example, map `accounts.roles.update` to a message key; don't interpret its dots as a translation path. Render an unknown failure as a localized, actionable generic message, not an upstream English error. IDs, user content, shell commands, raw run logs and diagnostic output stay verbatim. API/CLI machine output stays stable. A future email renderer needs the **recipient's** language, not the Web request cookie.

## Rollout and release checks

1. **Prove one vertical slice:** root loader/provider, language switcher, titles, shared header and `/sign-in` (including loading/error states). Exercise both locales with an unsigned visitor. Keep the switcher out of general release until the supported journeys are complete.
2. **Migrate by journey:** landing/setup and the remaining auth flows first, then settings, runs and admin. Include tooltips, hidden labels, placeholders, empty states and recovery messages. Cover shared control changes in Storybook. Keep English copy unchanged unless intentionally editing it.
3. **Release gate:** run `bun run kpdev check`, `bun run kpdev test e2e`, and `bun run kpdev test auth` against a disposable `TEST_DATABASE_URL`; add `bun run kpdev test stories` and `bun run kpdev test ui` for shared UI edits. Pin existing English Playwright flows to `en-US`; add a Chinese flow to the appropriate existing project/test match. Assert raw SSR text, `<html lang>` and `<title>` before JS; then assert hydration has no mismatch, navigation keeps the choice, clearing it resumes header negotiation, and two concurrent requests with opposing cookies do not bleed into each other. Test switching mid-password-reset without losing token/input, and leaving logs and callback parameters unchanged.
4. **Expand only with a consumer:** when Mobile actually adopts the same keys, extract the shared locale model and reusable messages into `@kipivo/i18n`; leave Web request/cookie code and Web-only copy behind. Cross-device preferences are a separate account/API migration with an explicit sign-in precedence rule, not a prerequisite for translation.

## Upstream references

- [Standalone React and core APIs](https://next-intl.dev/docs/environments/core-library): `IntlProvider`, `useTranslations` and `useFormatter` come from `use-intl`; non-component code can use `createTranslator` and `createFormatter` from `use-intl/core`. No Next.js plugin or routing middleware is needed.
- [Type-safe messages](https://next-intl.dev/docs/workflows/typescript#type-safe-arguments) and [the standalone hook](https://github.com/amannn/next-intl/blob/main/packages/use-intl/src/react/useTranslations.tsx): augment `AppConfig.Messages` on `use-intl` from the source catalog. JSON retains key names, not literal message types; v1 promises typed keys and cross-catalog CI validation, not compile-time ICU argument inference. If the latter becomes a requirement, use a literal-typed source catalog or generated declarations; do not introduce `next-intl/plugin` into Vite.
- [Provider configuration](https://github.com/amannn/next-intl/blob/main/packages/use-intl/src/react/IntlProvider.tsx) and [formatter source](https://github.com/amannn/next-intl/blob/main/packages/use-intl/src/core/createFormatter.tsx): the caller supplies messages and can provide an explicit time zone. Keep that configuration identical between SSR, React and route metadata.
