# Web internationalization

The home page, `/sign-in`, `/sign-up`, `/forgot-password` and `/reset-password` share a language preference and support English and Simplified Chinese. The preference belongs to the browser. Auth URLs, API payloads, email content and callback parameters are independent of the selected language.

The catalogs are compiled with [Paraglide JS](https://paraglidejs.com) from `packages/i18n`. Every message is a typed function on `m`, so call sites read `m.signInHeading()` — there are no namespaces, no message table at runtime and no locale prop to thread.

## Using messages on a page

1. Import `{ m } from "@kipivo/i18n/messages"` and call the message: `m.signInHeading()`, `m.socialContinueWithProvider({ provider })`.
2. Rich text stays in the message; render it with `renderMarkup` from `@kipivo/i18n` and a renderer per tag: `renderMarkup(m.signInSignUpPrompt(), { link: (chunks) => <Link>{chunks}</Link> })`. Use `stripMarkup` for plain-text surfaces such as `aria-label`.
3. Route titles use the same functions in `head: () => ({ meta: [{ title: m.signInDocumentTitle() }] })`.

## Locale resolution and switching

`packages/i18n/project.inlang/paraglide.config.ts` defines the shared strategy: the `locale` cookie, then the browser's preferred languages, then `en`. `apps/web/src/start.ts` runs `paraglideMiddleware` as a request middleware, so every message call during server rendering resolves the same locale through async local storage. Client and server read the same cookie, so hydration never disagrees with the HTML.

Selecting English or Simplified Chinese in the header re-renders the page in place. Auth forms keep their inputs, password visibility, pending requests and feedback. Errors are stored as keys so visible feedback follows the new language, and invalidating the route matches updates the document title. Choosing “Use browser language” writes a `locale-auto` marker and reloads. On `/reset-password`, reopen the link from the email after a reload because the page removes the token from the URL and holds it in memory. While the marker is set, the server ignores the remembered locale and the client drops the resolved-locale cookie Paraglide writes. Selecting an explicit language clears the marker.

## Editing messages

Edit `locales/en.json` and `locales/zh-CN.json` from the repository root. The `locales` symlink points to the catalogs owned by `@kipivo/i18n`. Messages use flat `camelCase` ids (`signInHeading`, `credentialEmail`, `socialContinueWithProvider`). Add the id to `en.json`, then to `zh-CN.json` unless the surface is English-only.

Administrator setup uses English for its page-specific copy and the active locale for its shared credential fields. Paraglide falls back to the base locale for the setup-specific messages listed in `packages/i18n/src/messages.test.ts`. The magic-link and email-code pages still use English, including their shared email form and return link. Signed-in pages are outside this translation scope. Keep ICU arguments (`{provider}`, plurals) and rich text placeholders (`<email/>`) in the message so translators can reorder the sentence.

`@kipivo/i18n` compiles the catalogs once into `packages/i18n/generated` (ignored by Git) and exports the result as `@kipivo/i18n/messages`, `@kipivo/i18n/runtime` and `@kipivo/i18n/server`. Every app and shared package imports those entries, so there is one runtime instance and `setLocale` updates every screen. `bun run paraglide:compile` runs the package's `compile` task before `dev`, `build`, `typecheck` and `test`; the preconfigured `paraglide()` plugin from `@kipivo/i18n/vite` recompiles on message edits, so apps never depend on the compiler or repeat the project paths. Desktop and future Tauri builds use the same package entries.

## Shared packages and components

A package under `packages/` may render copy and still stay app-agnostic:

```tsx
import { m } from "@kipivo/i18n/messages";

export function AccountSummary() {
  return <p>{m.accountSummary()}</p>;
}
```

Declare `"@kipivo/i18n": "workspace:*"` in that package and import the compiled entries, never an app alias. Because the compiled module is a single instance, switching the language in the header re-renders shared packages too. Presentational components that are locale-agnostic, such as `PasswordInput`, still take their labels as props.

Only the Web dev server runs the compiling Vite plugin; Storybook and other consumers run the package's `compile` task first (Turbo does this before `build`, `typecheck` and `test`), so two dev servers never write `generated/` at the same time.

Run `bun run kpdev i18n compile` to regenerate `packages/i18n/generated` and `bun run kpdev i18n check` to report unused or missing message ids without running the whole suite. `bun run kpdev check` covers catalog parity, markup rendering and language negotiation tests. `bun run kpdev test auth` with a disposable `TEST_DATABASE_URL` covers request isolation, in-place switching and the English-only boundary.
