# Web

- Compose each screen in its route file, alongside its navigation guards. Extract forms, lists, hooks, and clients by responsibility into `src/features/<feature>/`; avoid a `*-page.tsx` that only forwards an entire screen to one route. Keep HTTP handlers in `src/routes/`. Change the route source, not `src/routeTree.gen.ts`; the Web build and type check regenerate it.
- Prefer the shared shadcn components from `@kipivo/ui` for controls and forms. Add missing reusable controls in the UI workspace using its existing `base-nova` configuration; keep links, headings, and plain layout semantic.
- For new tabular data lists, use TanStack Table (`@tanstack/react-table`) for row and column state and shadcn components from `@kipivo/ui` for rendering the table and its controls. Keep feature-specific columns in the owning feature. When the API paginates, sort and filter on the server rather than only within the loaded page.
- Use `@/` for imports across Web source directories and `@assets/` for files in the repository’s shared `assets/` folder. Keep sibling imports relative and import workspaces through their `@kipivo/*` exports. Both Vite and Vitest resolve these aliases from `tsconfig.json`.
- Use a named `.tsx` file for a leaf page (e.g. `(auth)/sign-in.tsx` or `_app/admin/accounts.tsx`). Use a directory with `route.tsx` when the route owns child routes or a shared layout. Use `route.ts` for HTTP-only endpoints (including `$` splats and `$id` parameters). Keep `__root.tsx` for the root layout and `index.ts[x]` for an exact index match, such as `api/local/runs/index.ts` alongside `$id/route.ts`.
- Keep the document and global providers in `__root.tsx`, the landing layout in `index.tsx`, and shared page chrome in `_app/route.tsx`. `(auth)/route.tsx` is a sibling layout for `/sign-in` and `/setup`: it owns a full-height main landmark with the theme selector in the upper-right corner. Center its narrow form column and optional brand panel inside the content gutter. The landing page uses `AppFrame` for its header and navigation. Render child routes with `Outlet`; keep HTTP routes outside these visual layouts.
- Put workspace destinations in `src/layout/workspace-nav.tsx`. The operation routes share a desktop sidebar and a mobile bottom bar; both use the same links and permission checks. The workspace shell lives in `src/layout/`. Keep responsive Tailwind utilities with the components and workspace theme tokens in `src/styles/globals.css`. The theme switch animation lives in `src/styles/theme-transition.css`. The task board, local run inspector, and design guide serve `/workbench`, `/runs` (development only), and `/design-guide`. Public and auth pages keep their own chrome.
- Treat a `createServerFn` as callable by the browser. Validate its input and enforce the caller's session and permissions on the server before reading private data or mutating state. A route redirect or `useAccountSession()` is not authorization. For account operations, use the [protected API procedure](../api/AGENTS.md) with the incoming session rather than trusting a user ID or role from the client.
- Keep server environment reads and `@kipivo/runtime/local/connection` in `.server.ts` modules marked with `@tanstack/react-start/server-only`. Browser and server can both use `@kipivo/contracts/runs`. See the [local runner boundary](../../docs/architecture.md) and the [API proxy](src/api-proxy.server.ts) for how cookies and Origin reach the upstream API.
- For slow renders, request waterfalls, or large bundles, use [React performance](../../.agents/skills/vercel-react-best-practices/SKILL.md). For compound components and shared state, use [component composition](../../.agents/skills/vercel-composition-patterns/SKILL.md). Apply the React guidance; use TanStack Start, not Next.js, for routing and server APIs.
- For `createServerFn` changes, read [Start core](../../.agents/skills/start-core/SKILL.md) and [server functions](../../.agents/skills/server-functions/SKILL.md). Exercise changed Web flows with `bun run test:e2e` from the repository root; for session-dependent flows use the [auth suite](../../packages/auth/AGENTS.md).
