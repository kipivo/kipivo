# API

- For a public procedure, start with the [oRPC contract](../../packages/api/src/contract.ts), then implement the handler in [procedures.ts](src/procedures.ts). The existing [procedure routes](src/routes/procedures.ts) expose the same router over `/rpc` and `/api/v1` and generate OpenAPI from the contract. Do not create a parallel Hono RPC contract. For a new HTTP route group instead, add it under `src/routes/` and mount it in [app.ts](src/app.ts).
- `app.ts` installs Hono request IDs and logging. The procedure routes pass the original request headers, request ID, logger, and access service into oRPC. Use the session-protected procedure middleware for authenticated operations: it resolves the actor from those headers and enforces the contract's trusted-Origin requirement. Keep resource-specific permission checks in the access service.
- The [runtime](src/runtime.ts) owns long-lived clients and supplies `AppServices` to `createApp`. Handlers borrow services through `requestServices(context)`; do not create database pools or auth instances in handlers. Supply test services to `createApp` for HTTP-level tests.
- Consult the [Hono skill](../../.agents/skills/hono/SKILL.md) for HTTP mechanics. Update the [route access table](../../docs/api.md) when access requirements change. Run `bun run test:e2e` for public flows and the [auth suite](../../packages/auth/AGENTS.md) for session-protected flows.
